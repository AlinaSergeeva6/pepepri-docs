# Getting started with HTTP integration.

1\.    **General Setting (Integration).**

Commonly, clients HTTP API should have user authentication.

There are a few auth types that may differ with credentials they use.

![(Pic 1.)](<../../../../.gitbook/assets/1 (5).png>)



Here we will only highlight Basic Auth type.

So first thing you need to do is to add the credentials to Pepperi integration as settings.

You can to do so by adding apiuser and apipass setting to the General Settings of the integration profile (Pic 1.). Please note, that, obviously, setting application must be Generic HTTP Connector in our case.

![](<../../../../.gitbook/assets/2 (7).png>)

\
2\.    **Dataflow task setup for retrieving data.**

To get data from your client’s API via dataflow task you need to configure it properly.

Firstly, create dataflow task with appropriate parameters. Lets take Account Upload as an example.

![](<../../../../.gitbook/assets/3 (5).png>)

**Task Name** - whatever task name you need (Accounts in this example case)&#x20;

**Application**  - Generic HTTP Connector&#x20;

**Source Object** - Generic HTTP Exporter&#x20;

**Target Object** - Depending on data you want to upload on Pepperi (Pepperi Export Account in this case)

&#x20;   After that we need to configure a data source. In this case we retrieving data by GET call with URL provided by client. Depending on the client’s data and API structure, the link appearance may vary. Go to Dataflow Task settings -> HTTP.

![](<../../../../.gitbook/assets/4 (2).png>)

**Method** - Depending on the API structure. POST or GET commonly (GET in this example)

**Auth Type** -  Depending on the API structure (Basic in this example) . [https://developer.mozilla.org/en-US/docs/Web/HTTP/Authentication](https://developer.mozilla.org/en-US/docs/Web/HTTP/Authentication)

**URL**  - Call URL given by client you working with

### &#xD;Request headers

#### Authorization

This is one of the most essential configurations to be made.

Working with Basic Auth Type in Pepperi requires Authorization header to be configured.

The header itself looks like:

_**Authorization: Basic $#ApiKey#$**_, where _**$#ApiKey#$**_ is key, generated by using Username and Password of HTTP API user.

To generate it using Integration platform you need to set 2 settings:

![](<../../../../.gitbook/assets/image (517).png>)

And in HTTP tab add such string as header\
**Authorization: Basic {#base64(!%apiuser%!\\:!%apipass%!)#}**

\
The easiest way to obtain it is Postman.

By using Authorization tab of Postman and providing Username and Password, the software will generate necessary headers you may use in Integration.

![](<../../../../.gitbook/assets/5 (1).png>)

![](<../../../../.gitbook/assets/6 (3).png>)

#### Content-Type

Depending on the API configuration you also require to set the content type as one of the headers. In this example we are using the most common JSON content type.
