---
description: >-
  A Pager is a type of a Crawler where instead of having a source and a target
  URLs, only has a single pager URL. Pagers can be used to execute logic in
  between Crawlers or as a dynamic callback.
---

# 🔂 Pager

{% hint style="info" %}
A Pager cannot be used in `crawl` endpoint, it must be one of the crawlers of a `multi_crawl` operation.
{% endhint %}

<pre class="language-typescript" data-title="PagerCrawlerInput Interface" data-full-width="true"><code class="lang-typescript">// This is the API for a Pager declaration 
{
    Name: string;
    BlockID?: string; // Used to define execution order.
<strong>    PagerRelativeURL: string;
</strong>    PagerData: { [key: string]: unknown };
    Type: 'Pager';
    PagerOutputs: CrawlerTargetOutputBlueprint[]; // Interface in `Crawl` page.
}
</code></pre>

{% code title="PagerInput Interface " overflow="wrap" fullWidth="true" %}
```typescript
// This is the request body that PagerRelativeURL will get.
{
    /**
     * The key of the next page in the pager response, first will always be undefined.
     */
    PageKey: string | undefined;

    /**
     * Deconstruction of PagerData.
     */
    [key: string]: unknown;
}
```
{% endcode %}



{% code title="PagerOutput interface" overflow="wrap" fullWidth="true" %}
```typescript
// This is the response epxected from PagerRelativeURL.
{
     /**
     * A key that can be used to mark the working page of the pager, will be sent in next request as PageKey.
     * If undefined - the crawler will stop calling the pager.
     */
    NextPageKey: string | undefined;
    
    /**
    * Outputs generated by the page handling.
    */
    Outputs?: {
        [FieldID: string]: unknown[] | number;
    };
}
```
{% endcode %}
